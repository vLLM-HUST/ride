# 独立 Controller 的效果验证契约

这是M6的测量设计，不是实验结果，也不授权资源或发布。实际进度仍只在[统一路线图](CONTROLLER_ROADMAP.md)维护。每轮须另行冻结实际输入、源码、资源身份、绝对截止和验收阈值，沿控制面实验SOP执行。

## 要回答的问题

独立托管与API协作首先提供可部署、可恢复的工程能力；它们不会自动带来吞吐或成本收益。当前实例策略按请求需求调副本，扩容存在模型冷启动，缩容必须等任务和KV动作排空。需检验：需求变化时是否及时用到新增容量、空闲时是否归还模型资源预约，以及为此增加了多少等待和启动开销。

例如，一个突发已经完成后新副本才Ready，启动成功也可能没有业务价值。若紧接着还有下一次突发，保留副本可能减少再次启动；保留时间过长又占用资源。短突发、长突发和间隔变化必须分别测，不能只给能覆盖冷启动的长请求。

## 对照与因果边界

| 对照 | 目的 | 不能由它推出 |
|---|---|---|
| 固定1副本 | 单模型容量与最低常驻预约参照 | 动态策略胜过成熟扩缩容 |
| 固定2副本 | 相同最大容量下的延迟参照 | 多用一张卡就是调度收益 |
| 合理延迟的动态策略 | 在线可行的主要简单基线 | 当前实现等同Ray Serve官方算法 |
| 零延迟动态策略 | 诊断冷启动、重复启停和控制开销 | 仅胜过它就具有新颖性或总体优势 |

各组使用同一限流层、KV后端、模型版本与参数；只改事前声明的副本范围及扩缩延迟。固定副本也走相同RIDE/Controller接口，避免把不同代理路径混入扩缩收益。进一步研究主张须增加相关工作的最强可行基线，不能用这四组直接宣称论文贡献。

来源依据：[Ray Serve autoscaling](https://docs.ray.io/en/latest/serve/autoscaling-guide.html)说明请求驱动副本调整与Ray节点扩缩是不同层；[高级配置](https://docs.ray.io/en/latest/serve/advanced-guides/advanced-autoscaling.html)说明目标请求数、扩缩延迟以及慢初始化的保留取舍。本项目仅复用这一类简单思路，未迁移完整Serve实现。

## 工作负载和时间

输入文件冻结每个program的首轮提示、输出上限、后续提示、工具等待和ready时刻。客户端无并发槽位、无业务timeout、无业务重试；续轮使用上一轮真实输出。任务完成显式release，工具等待不算结束。不使用未来到达信息控制副本。

先测短突发和长突发，保持其余轴不变；再单独移动突发间隔。到达安排由冻结时间定义，不等待新副本Ready后才发业务。r37为功能资格刻意等待B Ready再发新任务，不可回填为这里的性能样本。不同组输出不同须保留实际token数与历史SHA；答案正确率另行判断。

分开计时：平台准备、安装检查、每个模型冷启动、整批业务、控制/排空、归档清理。模型启动结束不能当业务time0以隐藏冷启动；若另有暖机稳态试验，单列样本和资源账。

## 观测和核算

请求层保存ready/start/finish、成功/失败/取消/未完成、program和实际后端归属、实际输出、token数。program层保存每轮依赖、等待、release和完整完成时间。模型层保存Job、设备身份、Ready/终止、原生请求/token计数增量和实际资源授予证据。Controller层保存需求、期望副本、观测副本、决策原因、操作ID及执行结果，关联精确模型Job。

输出完整批次makespan、逐请求和program延迟分布、完成率、启动次数、Ready等待与排空时间。同时报告模型设备预约秒和平台申请设备秒。Ray Job存活时间包含初始化和其他阶段，不能替代精确设备预约；缺资源授予时刻则标Unknown，保留可证明的时间范围，不填0、不据此计算节约百分比。固定2卡RayCluster里停一个模型，释放的是集群内可用容量，平台仍申请2卡。

## 事前门槛与执行顺序

1. 软件负例及实际镜像门禁通过，再做少量真实完整program资格；无动作先查调用链，不扩大压力。
2. 冻结匹配发现对照，先确认所有program与请求终态；失败或资源期限中止保留，未完整不报makespan收益。
3. 单组结果只定位机制。正式判读至少三组交替顺序重复，并另冻未参与参数选择的留出输入；每个配对及离散度保留。
4. 时延和预约开销联合判读。若一快一贵，给出取舍，不自行宣称“总体更优”；若缺最强对照或精确成本，只报告已测维度。
5. 若动态策略没有支配强基线，记录负结果及适用边界，下一步依证据选问题，不调整阈值保证收益。

当前原生KV后端只读，不能把上述结果称为KV迁移收益。真实复制需要支持完成确认、目标覆盖和源保留的既有后端；后端不支持时在动作前拒绝，控制面不另造传输引擎。
