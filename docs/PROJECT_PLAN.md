# RIDE 项目中长期规划

负责人：毛言粲（myc）。执行开发者：当前开发代理。版本：2026-11-05，第一版。

这份文件规定目标、边界与阶段验收；[跨仓库路线图](architecture/CONTROLLER_ROADMAP.md)记录任务和实际状态；[系统设计](architecture/INDEPENDENT_CONTROLLERS.md)规定模块责任和接口。三者不各写一套进度。下述周期是排期参考，从各阶段开始计算，受实际验收与资源可用性影响，不是已承诺的完成日期。

## 1. 项目要达到什么结果

让推理系统开发者把请求、KV 和实例扩缩策略作为独立 Controller 开发、发布和运行，复用 RIDE 的统一安装、配置、托管、模型管理与观测能力。策略通过版本化 API 协作，Ray 提供分布式执行；RIDE 不成为推理数据代理，也不替代云平台。

工程目标：一个新策略仓库按同一开发契约接入，不复制另一 Controller 的内部实现，也不重新写部署系统。效果目标：在真实多轮推理工作负载下，测清控制策略对完成时间、服务质量和资源成本的作用及失效条件；无收益也按同一标准交付。研究目标：在可靠工程基础上，寻找独立策略协作时的跨层决策问题，不预设论文新颖性或正收益。

## 2. 近期：完成最小可用控制面（参考 2–4 周）

交付物：公共 RIDE SDK；独立 request-throttling-controller、kv-controller、instance-controller；统一插件入口、固定配置、身份、状态、日志和启停流程；一个已有 Ray 集群上的可复现示例。

开发顺序：SDK和实例包的软件基础 → 独立KV包 → 既有请求实现公共契约接入 → 集成既有成功部署修复 → 标准云端部署 → 真实模型闭环。具体任务与软件/云端/硬件状态只在跨仓路线图勾选。

验收必须同时满足：
- 三个仓库可以分别安装；只依赖公共 SDK，不 import 其他策略实现。
- 从 RIDE 标准入口发现、启动、查询、停止和恢复，各进程与模型 Job 身份可追踪。
- 扩容等待模型 Ready；缩容等待请求与 KV 双排空；工具等待不丢任务归属；并发外部模型不得被接管。
- 未知提交不自动重试；能力不支持在动作前拒绝；异常、停止隔离、管理进程接管有回归。
- 真实模型完成多轮请求和释放；所选 KV 后端执行其声明支持的实际动作并核输出/状态。若复制不支持，保留失败，不把接口通过当物理复制通过。

暂不做：多后端全面适配、多副本管理服务高可用、通用策略搜索、全套可视化管理平台。当前软件检查不是本阶段全部完成。

## 3. 中期：验证协作是否值得（参考随后 1–2 个月）

交付物：可重复工作负载、匹配对照、可观测性与故障恢复报告，以及有边界的策略建议。覆盖稳定负载、突发负载、多轮工具等待、容量竞争及缓存局部性变化；不是所有场景一次全部启动。

先选择一个问题和一个能触发机制的场景。比较原生服务、单项 Controller、必要的组合与完整系统；共同硬件/缓存/输入/输出约束，避免把更多副本的资源优势当调度优势。对照包括现有成熟策略；算法来源、薄适配与自行修改分别说明。

验收：完整批次与必要排空、至少三组交替重复、独立留出场景；同时记录任务完成/正确性、整批时间、尾延迟、缓存与重算、启动与搬运开销、模型预约设备秒和平台申请设备秒。排队等待、失败、未知和缺测保留，不能填零。指标和阈值在观察结果前冻结；负结果必须解释适用边界，不改门槛保证收益。

可观测性围绕请求 → 任务 → 模型 → Controller 决策 → 动作建立关联。先复用现有日志和指标，再补缺失字段；不先建设一个没有诊断问题驱动的大平台。

## 4. 长期：把控制面变成可扩展研究与复用基础（参考随后 3–6 个月）

在近期可靠运行、中期获得可信对照后，研究请求放行、缓存保留/处置和副本调整之间的联合代价。候选问题包括：缓存复用与扩缩冲突、迁移/重算/等待的选择、跨 Controller 的稳定性与资源预算。

每个候选先给问题证据、现有工作与最强简单基线，再实现最小算法并对照。只有实际发现耦合问题才加入协调机制；各 Controller 仍独立发布，公共层只承载稳定契约和确有复用需求的能力。

交付物：稳定版本化 API、兼容测试、至少一个外部策略按契约接入的复现案例、基于实测的技术文档或论文草稿。是否开源发布、投论文或增加平台能力由负责人决定；不把项目计划视为发布或无限资源授权。

## 5. 开发者怎样按规划工作

负责人决定目标、优先级、重大语义与发布边界；开发者负责梳理依赖、选取下一个可验收任务、实现、测试、归档和同步计划。日常可逆开发按已授权范围持续推进，不为每个实现细节重复询问。

每个任务在实现前明确：所属阶段、解决的问题、来源与依赖、交付代码、验收方法、失败处理和影响范围。先写能暴露问题的测试，再做必要修改；软件通过后才晋级云端与硬件。连续两次同因失败时重新检查前提，不盲目重跑。

每次阶段交付更新跨仓路线图，并报告：总目标进展、实际完成、证据与限制、未完成项、下一项工作。没有动作回执的事项标为未运行；不以文档、测试数或创建仓库代替系统可用。

## 6. 约束与当前起点

当前起点：SDK40项和独立实例包9项软件测试通过，隔离安装的模拟执行器闭环通过；真实跨仓 Ray/NPU/性能待验。原合集为来源与历史证据，不再增加正式策略。r19主动复制失败和最终物理进程核验Unknown保留，未由迁仓解决。

RIDE旧工作树已有未提交部署实现，本轮使用独立worktree；上云前集成实际成功链及身份门禁，不覆盖旧树或只取最早启动脚本。请求仓库保留ThunderAgent来源，旧合集简单请求实现的FIFO缺陷不得外推。

B1/SWE本轮不启动；其他聊天研究线保持独立。当前阶段不开新资源、不发布网站。未来资源窗口按实际对象、权限和最新批准范围独立冻结；不动shuhao资源，不中断他人活跃工作，不自动延长历史截止。
